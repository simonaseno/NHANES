NHANES Data Structure

Understand cycles, components, files, variables, records, and participant identifiers

Learn how NHANES data are organized and how to identify the correct files, variables, keys, and merge relationships before beginning analysis.

NHANES is a collection of linked data files

NHANES does not arrive as one complete analytical dataset.

Information is distributed across survey cycles, components, files, variables, and participant records.

Before writing a merge, you must understand:

  • what each file represents;
  • what one row represents;
  • which variables are available;
  • which identifier links records;
  • whether the relationship between files is one-to-one.

The five levels of NHANES organization

Survey program NHANES
Cycle Usually two years
Component Demographics, laboratory, examination, questionnaire
Data file One released dataset
Variable One measured or derived field

Explore the core building blocks

01

Survey cycles

NHANES continuous data are commonly released in two-year periods such as 1999–2000 or 2017–2018.

02

Components

Data are grouped into Demographics, Laboratory, Examination, Questionnaire, and Dietary components.

03

Files

Each released file contains a defined set of variables for a specific cycle and component.

04

Participant records

Many files contain one row per participant, but that assumption must always be verified.

Survey cycles

A survey cycle identifies the period during which data were collected and released.

Examples include:

1999–2000
2001–2002
2003–2004
2017–2018

Files from different cycles may use different suffixes.

For example:

DEMO_B.XPT
DEMO_C.XPT
DEMO_D.XPT

The suffix identifies the release cycle. It is not part of the scientific variable name.

Core principle: Always retain an explicit survey_cycle variable after importing a file. Do not rely only on the filename to remember where records came from.

NHANES components

NHANES separates information into major components.

  • Demographics
  • Laboratory
  • Examination
  • Questionnaire
  • Dietary

Demographic files commonly contain:

  • age;
  • sex;
  • race and ethnicity;
  • education;
  • income-related variables;
  • survey design variables;
  • examination and interview weights.

Demographic files are often used as the central participant-level source for analysis.

Laboratory files may contain:

  • complete blood count results;
  • biomarkers;
  • chemistry measurements;
  • infectious disease results;
  • environmental exposure measurements;
  • specimen-related variables.

A single laboratory topic may have different file names across cycles.

Examination files may contain:

  • body measurements;
  • blood pressure;
  • oral health;
  • physical-function measures;
  • other examination results.

Questionnaire files may contain:

  • medical conditions;
  • medication use;
  • smoking;
  • alcohol use;
  • occupation;
  • health behaviors;
  • health-care access.

Dietary files may include:

  • 24-hour dietary recall;
  • nutrient intake;
  • supplement use;
  • food-level records.

Some dietary files contain multiple rows per participant.

Anatomy of a data file

A typical NHANES file contains:

Rows      → observations or records
Columns   → variables
SEQN      → participant identifier
Labels    → human-readable descriptions
Values    → measured, reported, or derived data

The file may also contain metadata such as:

  • variable labels;
  • value labels;
  • special missing-value codes;
  • units;
  • survey design variables;
  • analytic weights.

The participant identifier: SEQN

SEQN is the principal participant identifier used to link many NHANES files.

A simplified example:

Demographic file

SEQN
age
sex
survey weight
Match
using
SEQN

CBC file

SEQN
hemoglobin
hematocrit
platelet count

After a valid merge, one analytical record may contain:

SEQN
survey cycle
age
sex
hemoglobin
hematocrit
platelet count
survey design variables
survey weight
WarningSEQN alone may not be sufficient after combining cycles

When multiple cycles are appended, use a cycle-aware key:

survey_cycle + SEQN

This preserves provenance and protects against accidental cross-cycle matches.

What does one row represent?

Never assume that one row always means one participant.

One row may represent:

  • one participant;
  • one examination;
  • one laboratory result;
  • one dietary recall;
  • one medication;
  • one food item;
  • one repeated measurement;
  • one event.

Before merging, ask:

What does one row represent in this file?

Common file relationships

One-to-one

Each participant appears once in each file.

1 participant ↔ 1 record

One-to-many

One participant may have several related records.

1 participant ↔ many records

Supplementary

A separate file may contain repeat or additional examinations.

primary record + supplementary record

Why merge relationships matter

Suppose the Demographic file contains:

10,000 participant records

and a laboratory file contains:

9,200 participant records

A left join from Demographics to Laboratory may preserve all 10,000 participants, with missing laboratory values for those without results.

A left join from Laboratory to Demographics may preserve only the 9,200 laboratory records.

Neither choice is automatically correct.

The correct join depends on the analytical population.

A merge can change the number of rows

Consider this example.

Demographic data:

SEQN
1001
1002
1003

Laboratory data:

SEQN
1001
1002
1002

Participant 1002 appears twice in the laboratory file.

A simple join can produce:

SEQN
1001
1002
1002
1003

The merged file now has four rows instead of three.

ImportantA successful join is not automatically a valid join

R may complete a join without producing an error even when the relationship is scientifically inappropriate.

Always validate:

  • uniqueness;
  • duplicates;
  • row counts;
  • unmatched records;
  • expected join relationships.

Investigate duplicates before removing them

Repeated identifiers may represent:

  • exact duplicate records;
  • repeat examinations;
  • supplementary measurements;
  • multiple specimen results;
  • conflicting records;
  • legitimate event-level data.

Do not immediately apply:

distinct(
  SEQN,
  .keep_all = TRUE
)

That command may silently remove scientifically meaningful information.

Instead, investigate:

data |>
  count(
    SEQN
  ) |>
  filter(
    n > 1
  )

Then inspect the repeated records.

Primary and supplementary files

Some cycles may contain more than one file associated with the same topic.

For the CBC pipeline, the 2001–2002 cycle includes:

L25_B
L25_2_B

The pipeline treats:

L25_B

as the primary CBC file.

It preserves:

L25_2_B

as a supplementary second-examination file.

The files are not blindly appended.

Core principle: Similar file names do not prove that files represent the same analytical population or examination occasion.

Variable names and labels

An NHANES variable commonly has:

  • a short variable name;
  • a descriptive label;
  • a data type;
  • coded values;
  • units;
  • documentation.

For example:

Variable: LBXHGB
Meaning: Hemoglobin
Unit: g/dL

The short name is convenient for programming.

The label and documentation provide the scientific meaning.

Variable names may change

Across cycles, a concept may:

  • keep the same variable name;
  • move to another file;
  • be renamed;
  • change units;
  • change method;
  • become unavailable;
  • apply to a different subsample.

Therefore, matching variable names alone is not sufficient for harmonization.

Use documentation as part of the data

For every variable used in an analysis, review:

  • variable description;
  • units;
  • eligible population;
  • measurement method;
  • missing-value codes;
  • analytic notes;
  • survey-weight guidance;
  • cycle-specific changes.

Documentation is part of the analytical evidence, not an optional extra.

Build a source catalog

A reproducible workflow should maintain a source catalog containing fields such as:

survey_cycle
component
file_name
file_role
source_url
local_path
primary_or_supplementary
expected_variables
notes

A source catalog helps prevent:

  • accidental omission of cycles;
  • use of the wrong file;
  • mixing primary and supplementary examinations;
  • undocumented manual downloads;
  • loss of provenance.

Data-structure decision challenge

Suppose you have:

DEMO_B
L25_B
L25_2_B

What should you do?

NoteReveal the recommended approach
  1. Treat DEMO_B as the Demographic source.
  2. Treat L25_B as the primary CBC source.
  3. Preserve L25_2_B separately as a supplementary second-examination file.
  4. Add survey_cycle = "2001–2002" to all three datasets.
  5. Validate SEQN within each file.
  6. Merge the primary CBC file with Demographics using survey_cycle + SEQN.
  7. Do not append the supplementary file to the primary CBC data without a scientifically justified rule.

Common data-structure mistakes

WarningMistake 1: Assuming every file is participant-level

Some files contain repeated or event-level records.

WarningMistake 2: Joining before checking uniqueness

Unexpected duplicates can multiply rows during a join.

WarningMistake 3: Losing cycle information

After appending files, records must retain their original survey cycle.

WarningMistake 4: Treating similar files as interchangeable

Primary and supplementary files may represent different examinations or populations.

WarningMistake 5: Harmonizing by variable name alone

The same name may have different methods, units, or eligibility across cycles.

Quick knowledge check

NoteWhat is SEQN?

SEQN is the principal participant identifier used to link many NHANES files.

NoteWhat key is safer after combining cycles? 
survey_cycle + SEQN
NoteDoes one row always represent one participant?

No. A row may represent an examination, result, event, recall, medication, or repeated measurement.

NoteWhy should duplicates be investigated before removal?

They may represent valid repeat or supplementary observations rather than accidental duplication.

NoteWhat should be checked before combining the same variable across cycles?

Review its definition, units, method, eligibility, documentation, and availability for each cycle.
