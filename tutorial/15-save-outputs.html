Lesson 15: Save Reusable Outputs

Export validated data, metadata, validation reports, and reproducibility information

Save the processed NHANES CBC and Demographic datasets in reusable formats with documentation and reproducibility metadata.
NoteLearning objectives

By the end of this lesson, you should be able to:

  • explain the difference between RDS and CSV outputs;
  • save validated datasets in reusable formats;
  • preserve R-specific metadata;
  • create compact analysis-ready extracts;
  • save variable dictionaries and validation reports;
  • record package versions and session information;
  • create an output manifest;
  • validate that every required output exists.

Why output design matters

A reproducible pipeline should not end with objects that exist only in the current R session.

The results should be saved in formats appropriate for:

  • future R analysis;
  • review in spreadsheet software;
  • sharing with collaborators;
  • validation and audit;
  • documentation;
  • reproducibility;
  • downstream reporting.

Different output formats serve different purposes.

RDS versus CSV

RDS

An RDS file preserves one R object.

It can preserve:

  • variable classes;
  • factors;
  • ordered factors;
  • labels;
  • dates;
  • logical variables;
  • list columns;
  • other R-specific attributes.

Read an RDS file with:

readRDS(
  "path/to/file.rds"
)

CSV

A CSV file is broadly accessible.

It can be opened with:

  • R;
  • Python;
  • Excel;
  • Google Sheets;
  • database tools;
  • text editors.

However, CSV does not preserve:

  • R factor levels;
  • ordered-factor status;
  • variable-label attributes;
  • object classes beyond plain text and numbers;
  • other R-specific metadata.

For this reason, the pipeline saves both:

RDS for analytical fidelity
CSV for portability

Why CSV classes may differ after reload

A CSV file stores plain values.

After reloading:

  • factors may become character;
  • ordered factors may become character;
  • labels are absent;
  • dates may require parsing;
  • logical values may be inferred differently.

That is expected.

Use the RDS file when R metadata must be preserved.

Common mistakes

Saving only CSV

CSV is portable but does not preserve R metadata.

Saving only RDS

RDS preserves metadata but may be less convenient for collaborators using other software.

Overwriting raw source files

Processed outputs should be stored separately from:

data/raw/

Failing to save validation reports

A dataset without its validation evidence is harder to audit.

Omitting package versions

Package behavior can change over time.

Assuming the CSV reload is identical to the RDS reload

The values may be similar, but classes and labels can differ.

Publishing every output automatically

Some files may be:

  • large;
  • temporary;
  • sensitive;
  • inappropriate for version control.

Review .gitignore and repository size before committing generated data.

Knowledge check

NoteWhy save both RDS and CSV files?

RDS preserves R-specific classes, labels, and factors, while CSV provides broad compatibility with other software.

NoteWhy create a separate variable dictionary?

Portable formats such as CSV do not preserve variable-label attributes, so the dictionary documents the meaning, source, and analytical use of variables.

NoteWhy calculate hashes for final datasets?

Hashes provide reproducible file fingerprints that help identify whether output files changed between pipeline runs.
