Lesson 18: Assemble and Run the Complete Pipeline

Organize the full script, run it from a clean R session, and verify every generated output

Assemble the completed NHANES CBC and Demographic pipeline into one reproducible script and validate the full execution.
NoteLearning objectives

By the end of this lesson, you should be able to:

  • organize the pipeline sections in their required execution order;
  • distinguish configuration, functions, processing, analysis, and outputs;
  • verify that the complete script can be parsed by R;
  • run the pipeline from a clean R session;
  • capture execution time and failure information;
  • confirm that the source catalog is valid;
  • verify that all primary and supplementary source roles are preserved;
  • confirm that all four figures are generated;
  • create a final pipeline-run summary;
  • distinguish running the R pipeline from rendering the Quarto website.

What this lesson accomplishes

In Lessons 1–17, you built the pipeline incrementally.

You now have code that:

  1. prepares the project;
  2. loads packages;
  3. validates the source catalog;
  4. downloads the NHANES source files;
  5. imports and inspects every XPT file;
  6. investigates the 2001–2002 second CBC examination;
  7. combines the primary CBC files;
  8. combines the Demographic files;
  9. merges the two components;
  10. validates the merged dataset;
  11. creates readable labels;
  12. saves reusable outputs;
  13. analyzes hemoglobin;
  14. creates four professional figures.

Lesson 18 does not introduce a new analytical method.

It organizes the completed work into a reproducible execution sequence.

The final pipeline file

The complete script should be stored as:

nhanes_pipeline.R

at the root of the project.

Your project should contain:

NHANES/
├── nhanes_pipeline.R
├── config/
├── data/
├── outputs/
├── R/
├── tutorial/
├── _quarto.yml
└── styles.css

Pipeline execution order

The sections in nhanes_pipeline.R should appear in this order:

Section 1: Project setup
Section 2: Package validation and loading
Section 3: Output-directory creation
Section 4: Source-catalog definition and validation
Section 5: Download one test file
Section 6: Download all source files
Section 7: Inspect all downloaded files
Section 8: Investigate and handle duplicate records
Section 9: Combine files within each component
Section 10: Merge CBC and Demographic data
Section 11: Validate the merged analytical dataset
Section 12: Create readable variable labels
Section 13: Save reusable outputs
Section 14: Analyze and prepare hemoglobin data
Section 15: Create professional hemoglobin figures
Section 16: Complete pipeline-run validation
ImportantExecution order matters

Later sections depend on objects created earlier.

For example:

  • file inspection requires the acquisition manifest;
  • duplicate handling requires imported source objects;
  • component combination requires the duplicate policy;
  • merging requires validated component datasets;
  • plotting requires the Lesson 16 summary datasets.

Do not rearrange sections casually.

Add the final pipeline-validation section

At the bottom of nhanes_pipeline.R, add:

# ============================================================
# SECTION 16: COMPLETE PIPELINE-RUN VALIDATION
# ============================================================

Record pipeline start time

Ideally, the pipeline start time should be recorded near the beginning of the script.

Near the top of nhanes_pipeline.R, add:

pipeline_started_at <- Sys.time()

At the end of the script, calculate the finish time:

pipeline_finished_at <- Sys.time()

Calculate elapsed time:

pipeline_elapsed_seconds <- as.numeric(
  difftime(
    pipeline_finished_at,
    pipeline_started_at,
    units = "secs"
  )
)

Check the script before running it

Save the file

In VS Code, open:

nhanes_pipeline.R

Press:

Command + S

Check whether R can parse the script

Open the terminal at the project root and run:

Rscript -e 'parse(file = "nhanes_pipeline.R"); cat("Script parsed successfully.\n")'

A successful result ends with:

Script parsed successfully.

A parsing failure means the script contains a structural syntax problem such as:

  • a missing parenthesis;
  • a missing brace;
  • an incomplete quotation mark;
  • a malformed operator;
  • an unfinished function;
  • a copied Markdown fence inside the R script.
WarningParsing does not run the pipeline

This command checks the script’s R syntax.

It does not:

  • download files;
  • process data;
  • create datasets;
  • generate figures.

Run from a clean R session

Why use a clean session?

A script can appear to work because objects from previous interactive work remain in memory.

A reproducible pipeline must create every required object itself.

Using Rscript starts a separate R process and reduces dependence on the current VS Code session.

Run the complete pipeline

From the project root, run:

Rscript nhanes_pipeline.R

Leave the terminal open while it runs.

The script may take time because it can:

  • validate packages;
  • download source files;
  • import multiple XPT files;
  • create hashes;
  • write large processed datasets;
  • export twelve figure files;
  • produce validation reports.

Save the console output to a log

For a reproducible execution log, run:

Rscript nhanes_pipeline.R 2>&1 | tee outputs/validation/complete_pipeline_console.log

This displays the output in the terminal and saves it as:

outputs/validation/complete_pipeline_console.log

Check the exit status

Immediately after the pipeline finishes, run:

echo $?

Expected:

0

An exit status of 0 means the R process completed without an unhandled error.

A nonzero status means the run failed.

Do not run the entire script repeatedly while debugging

When an error occurs:

  1. read the first error message;
  2. identify the section named in the message;
  3. inspect the relevant object or file;
  4. fix the underlying problem;
  5. restart from a clean session;
  6. run the complete script again.

Avoid repeatedly executing later sections against partially created objects.
