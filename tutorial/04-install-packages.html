Install the Required R Packages

Prepare the tools used to download, read, transform, validate, and visualize the data

Install, load, and validate the R packages used by the NHANES pipeline.
NoteLearning objectives

By the end of this lesson, you should be able to:

  • explain what an R package is;
  • distinguish installation from loading;
  • identify the packages required by the pipeline;
  • install only packages that are missing;
  • load packages programmatically;
  • record package versions and session information.

What is an R package?

An R package is a collection of:

  • functions;
  • documentation;
  • datasets;
  • supporting code.

Packages add specialized capabilities to R.

Packages used in this tutorial

Package Purpose
httr Downloads files through HTTP
haven Reads SAS transport .xpt files
dplyr Transforms, joins, counts, and combines data
readr Writes CSV files
tibble Creates readable data tables
ggplot2 Creates graphs
digest Calculates file hashes
purrr Supports structured iteration
stringr Handles text consistently

Installing and loading are different

Installing

Installation places a package on the computer.

install.packages(
  "dplyr"
)

This usually needs to be done only once for a particular R library.

Loading

Loading makes the package available in the current R session.

library(
  dplyr
)

This normally needs to happen each time a new R session begins.

Add the package section

Add this below the directory section in nhanes_pipeline.R:

# ============================================================
# SECTION 2: INSTALL AND LOAD REQUIRED PACKAGES
# ============================================================

required_packages <- c(
  "httr",
  "haven",
  "dplyr",
  "readr",
  "tibble",
  "ggplot2",
  "digest",
  "purrr",
  "stringr"
)

packages_to_install <- required_packages[
  !vapply(
    required_packages,
    requireNamespace,
    logical(1),
    quietly = TRUE
  )
]

if (length(packages_to_install) > 0) {
  install.packages(
    packages_to_install,
    repos = "https://cloud.r-project.org"
  )
}

invisible(
  lapply(
    required_packages,
    library,
    character.only = TRUE
  )
)

message(
  "Required packages are installed and loaded."
)

Run the section.

The first run may produce installation messages.

Expected final message:

Required packages are installed and loaded.

Understanding requireNamespace()

This code:

requireNamespace(
  "dplyr",
  quietly = TRUE
)

checks whether dplyr is installed without attaching it.

It returns:

TRUE

or:

FALSE

Understanding vapply()

vapply() repeats the package check for every name in required_packages.

Only packages returning FALSE are included in:

packages_to_install

Validate the packages

Add:

package_check <- vapply(
  required_packages,
  requireNamespace,
  logical(1),
  quietly = TRUE
)

print(
  package_check
)

Every package should return:

TRUE

Stop if any package is unavailable:

if (!all(package_check)) {
  unavailable_packages <- names(
    package_check
  )[!package_check]

  stop(
    "Required packages are unavailable: ",
    paste(
      unavailable_packages,
      collapse = ", "
    )
  )
}

message(
  "Package validation passed."
)

Expected message:

Package validation passed.

Record package versions

Add:

package_versions <- tibble::tibble(
  package = required_packages,
  version = vapply(
    required_packages,
    function(package_name) {
      as.character(
        utils::packageVersion(
          package_name
        )
      )
    },
    character(1)
  )
)

print(
  package_versions
)

Save the table:

readr::write_csv(
  package_versions,
  file.path(
    "outputs",
    "validation",
    "package_versions.csv"
  )
)

Confirm:

file.exists(
  file.path(
    "outputs",
    "validation",
    "package_versions.csv"
  )
)

Expected result:

[1] TRUE

Record session information

Add:

session_information <- capture.output(
  sessionInfo()
)

writeLines(
  session_information,
  file.path(
    "outputs",
    "validation",
    "session_info.txt"
  )
)

Confirm:

file.exists(
  file.path(
    "outputs",
    "validation",
    "session_info.txt"
  )
)

Expected result:

[1] TRUE

Why session information matters

It records:

  • R version;
  • operating system;
  • attached packages;
  • loaded namespaces;
  • package versions.

This helps diagnose differences between computers and future environments.

Namespace notation

You will often see:

dplyr::filter()

The :: notation identifies the package containing the function.

This improves clarity and reduces conflicts between packages with similarly named functions.

Common problems

R cannot connect to CRAN

Check:

  • internet connection;
  • proxy settings;
  • firewall restrictions;
  • repository address.

The code uses:

https://cloud.r-project.org

Permission error

R may be trying to install packages in a protected system directory.

A user-level package library is usually preferable.

A package installs but cannot load

Restart the R session and rerun the section.

Function-name conflicts

Use explicit namespace notation:

dplyr::select()

instead of:

select()

when ambiguity is possible.

NoteWhat is the difference between installing and loading a package?

Installation places the package on the computer. Loading makes it available in the current R session.

NoteWhy check for missing packages before installing?

It avoids reinstalling packages that are already available.
