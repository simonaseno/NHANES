Lesson 11: Combine Files Within Each Component

Stack the ten primary CBC cycles and the ten Demographic cycles into validated longitudinal datasets

Combine primary NHANES CBC files and Demographic files across ten survey cycles while preserving provenance and validating participant keys.
NoteLearning objectives

By the end of this lesson, you should be able to:

  • identify the primary source files for each component;
  • verify that each survey cycle is represented once;
  • compare source schemas before row binding;
  • combine CBC files across ten cycles;
  • combine Demographic files across ten cycles;
  • preserve survey-cycle and source metadata;
  • validate the composite key survey_cycle + SEQN;
  • distinguish structural missingness from data errors;
  • create component-level validation reports.

Why combine within components first?

The CBC and Demographic files should not be merged immediately after download.

A safer workflow is:

  1. inspect every source independently;
  2. separate supplementary records;
  3. combine all primary CBC sources;
  4. combine all primary Demographic sources;
  5. validate both combined components;
  6. merge the validated component datasets.

This keeps component-specific problems visible before the final join.

Compare schemas before combining

Files from different survey cycles may not contain identical columns.

Create a schema inventory function:

create_schema_inventory <- function(
    source_list) {

  purrr::imap_dfr(
    source_list,
    function(
        data,
        dataset_id) {

      tibble::tibble(
        dataset_id = dataset_id,
        variable = names(
          data
        ),
        variable_class = purrr::map_chr(
          data,
          function(variable) {
            paste(
              class(
                variable
              ),
              collapse = "; "
            )
          }
        )
      )
    }
  )
}

ImportantMissing columns after row binding may be structural

When a variable exists in some cycles but not others, dplyr::bind_rows() creates that column in the combined dataset and fills unavailable cycles with NA.

Those missing values can mean:

The variable did not exist in that source cycle.

They do not necessarily mean:

The participant had a missing result.

This distinction should be preserved during interpretation.

Standardize the composite key columns

Before combining sources, ensure that:

  • SEQN is numeric;
  • survey_cycle is character.

Create a standardization function:

standardize_component_keys <- function(
    data) {

  if (
    !"SEQN" %in%
      names(data)
  ) {
    stop(
      "SEQN is missing from a source dataset."
    )
  }

  if (
    !"survey_cycle" %in%
      names(data)
  ) {
    stop(
      "survey_cycle is missing from a source dataset."
    )
  }

  data |>
    dplyr::mutate(
      SEQN = as.numeric(
        SEQN
      ),
      survey_cycle = as.character(
        survey_cycle
      )
    )
}

Apply it to the CBC list:

primary_cbc_sources <-
  purrr::map(
    primary_cbc_sources,
    standardize_component_keys
  )

Apply it to the Demographic list:

primary_demographic_sources <-
  purrr::map(
    primary_demographic_sources,
    standardize_component_keys
  )

Why use survey_cycle + SEQN?

The source-level identifier is:

SEQN

After combining multiple cycles, this tutorial uses:

survey_cycle + SEQN

as the explicit analytical key.

This makes the cycle-participant relationship visible and avoids relying on an undocumented assumption that SEQN alone is globally unique across every release.

Important interpretation principle

After row binding, NA values can have different meanings.

Participant-level missingness

The variable existed in that cycle, but the participant has no recorded value.

Structural missingness

The variable was not included in that source cycle, so every participant from that cycle receives NA after binding.

Before analyzing a variable across cycles, determine which form of missingness is present.

Common mistakes

Including the second CBC examination

Only the ten primary CBC sources belong in:

cbc_primary_1999_2018

Combining before reviewing schemas

Column names and classes should be inspected before row binding.

Assuming every NA means missing participant data

Some NA values are created because a variable was unavailable in a survey cycle.

Using SEQN without cycle context

The explicit combined-data key is:

survey_cycle + SEQN

Losing source provenance

Metadata should be added before binding so each row remains traceable.

Ignoring class mismatches

A variable stored as different classes across cycles can cause binding errors or unintended coercion.

Knowledge check

NoteWhy combine CBC and Demographic files separately before merging them?

It allows each component’s source coverage, schema, row counts, keys, and provenance to be validated independently before the final join.

NoteWhat happens when bind_rows() encounters a variable absent from one cycle?

It creates the combined column and inserts NA for records from the cycle where that variable was unavailable.

NoteWhy is survey_cycle + SEQN used as the combined-data key?

It explicitly identifies a participant within a survey cycle and avoids relying on an undocumented assumption that SEQN alone is globally unique across all releases.
