Lesson 10: Investigate and Handle Duplicate Records

Separate the 2001–2002 second CBC examination and preserve duplicate evidence before combining cycles

Investigate repeated participant keys in the NHANES CBC source files and preserve the second examination separately.
NoteLearning objectives

By the end of this lesson, you should be able to:

  • explain why repeated SEQN values require investigation;
  • distinguish duplicates within one source from overlap across sources;
  • compare the 2001–2002 primary and second CBC examinations;
  • identify participants appearing in both files;
  • distinguish exact duplicate rows from different measurements;
  • preserve the second examination as supplementary data;
  • create duplicate-audit reports;
  • prepare a clean set of primary CBC sources for combination.

Why duplicate handling matters

A duplicate participant key is not automatically an error.

Repeated identifiers can represent:

  • an exact duplicate row;
  • a repeat examination;
  • a second specimen;
  • a complementary record;
  • conflicting values;
  • a source with more than one row per participant;
  • the same participant appearing in more than one source file.

Deleting repeated records without understanding their meaning can remove scientifically valuable information.

The specific issue in this pipeline

The 2001–2002 CBC release contains two relevant files:

L25_B
L25_2_B

In this tutorial:

  • L25_B is treated as the primary CBC examination;
  • L25_2_B is treated as a supplementary second examination.

Some participants may appear in both files.

Appending both files directly into one primary person-level dataset would create repeated participant-cycle keys.

WarningDo not use this shortcut 
dplyr::distinct(
  SEQN,
  .keep_all = TRUE
)

This keeps one arbitrary row and discards the others.

It does not determine whether the discarded records are:

  • exact copies;
  • repeat measurements;
  • complementary observations;
  • conflicting observations.

find_duplicate_keys <- function(
    data,
    key_columns) {

  data |>
    dplyr::count(
      dplyr::across(
        dplyr::all_of(
          key_columns
        )
      ),
      name = "occurrences"
    ) |>
    dplyr::filter(
      occurrences > 1
    )
}

Why compare only shared variables?

A row cannot be classified as an exact duplicate when the two source schemas differ unless comparison is restricted to variables available in both sources.

Even then, identical values across common variables do not prove that the two source files are conceptually interchangeable.

The source role must still be preserved.

Build a value-comparison function

Create:

values_equal_with_missing <- function(
    first_value,
    second_value) {

  dplyr::case_when(
    is.na(first_value) &
      is.na(second_value) ~ TRUE,

    is.na(first_value) |
      is.na(second_value) ~ FALSE,

    TRUE ~ first_value ==
      second_value
  )
}

shared_measurement_comparison <-
  purrr::map_dfr(
    measurement_variables,
    function(variable_name) {

      primary_column <- paste0(
        variable_name,
        "_primary"
      )

      second_column <- paste0(
        variable_name,
        "_second"
      )

      tibble::tibble(
        SEQN =
          shared_second_exam_comparison$SEQN,
        variable =
          variable_name,
        primary_value =
          shared_second_exam_comparison[[
            primary_column
          ]],
        second_exam_value =
          shared_second_exam_comparison[[
            second_column
          ]],
        values_match =
          values_equal_with_missing(
            shared_second_exam_comparison[[
              primary_column
            ]],
            shared_second_exam_comparison[[
              second_column
            ]]
          )
      )
    }
  )

Summarize differences by variable

Run:

second_exam_variable_difference_summary <-
  shared_measurement_comparison |>
  dplyr::group_by(
    variable
  ) |>
  dplyr::summarise(
    compared_participants =
      dplyr::n(),
    matching_values =
      sum(
        values_match,
        na.rm = TRUE
      ),
    different_values =
      sum(
        !values_match,
        na.rm = TRUE
      ),
    percent_different =
      100 *
      different_values /
      compared_participants,
    .groups = "drop"
  ) |>

    dplyr::desc(

Classify each shared participant

Create a participant-level summary:

second_exam_participant_comparison <-
  shared_measurement_comparison |>
  dplyr::group_by(
    SEQN
  ) |>
  dplyr::summarise(
    compared_variables =
      dplyr::n(),
    matching_variables =
      sum(
        values_match,
        na.rm = TRUE
      ),
    different_variables =
      sum(
        !values_match,
        na.rm = TRUE
      ),
    all_common_values_match =
      all(
        values_match
      ),
    .groups = "drop"
  ) |>
  dplyr::mutate(
    comparison_class =
      dplyr::case_when(
        all_common_values_match ~
          "all_common_values_match",

        different_variables > 0 ~
          "different_measurements",

        TRUE ~
          "unresolved"
      )
  )

Inspect:

print(
  second_exam_participant_comparison,
  n = Inf
)

Interpret the comparison classes

all_common_values_match

All compared common values are identical.

This is evidence of a value-level match across the shared variables.

It does not justify deleting the supplementary source because:

  • source roles differ;
  • source provenance differs;
  • nonshared variables may differ;
  • the records belong to separate examination contexts.

different_measurements

At least one common variable differs between the primary and second examinations.

This indicates that the second record contains distinct measurements.

unresolved

The comparison could not be classified completely.

This category should be preserved and investigated.

Why the second examination is not discarded

The second examination remains valuable for:

  • repeat-measurement analysis;
  • within-person comparison;
  • measurement stability;
  • quality-control investigation;
  • methodological research;
  • sensitivity analyses.

Its exclusion from the primary stack is an analytical design decision, not a judgment that the data are invalid.

Why source roles must remain explicit

The following two statements are different:

This row is a duplicate.
This participant has a second examination.

The first implies redundancy.

The second describes study design.

The pipeline preserves that distinction through:

source_exam
analysis_role
source_file_id
inclusion_in_primary_stack

Appending L25_B and L25_2_B

This creates repeated participant-cycle keys in the main CBC stack.

Deleting the second examination

This loses scientifically useful repeat-measurement data.

Using distinct(SEQN, .keep_all = TRUE)

This keeps an arbitrary record without scientific justification.

Pipeline metadata and source-specific variables may differ even when scientific measurements match.

Calling all shared participants exact duplicates

The same participant appearing in both files does not mean the measurement values are identical.

Treating identical common values as proof of redundancy

Identical values across shared variables do not erase differences in source role, examination context, or nonshared variables.

NoteWhy should L25_2_B not be appended to the primary CBC stack?

It represents a second examination for participants who may already appear in L25_B. Appending it would create repeated participant-cycle keys and mix primary and repeat measurements.

NoteDoes a shared SEQN prove that two rows are exact duplicates?

No. It proves only that the same participant appears in both sources. Measurement values and source context must still be compared.

NoteWhy preserve the second examination?

It may support repeat-measurement, reliability, quality-control, and methodological analyses even though it is excluded from the main primary stack.
