Lesson 14: Create Readable Variable Labels

Preserve NHANES metadata and create clear analytical labels without changing the original variables

Extract, review, and apply readable variable labels to the validated NHANES CBC and Demographic dataset.
NoteLearning objectives

By the end of this lesson, you should be able to:

  • explain the difference between variable names and variable labels;
  • extract labels imported from NHANES XPT files;
  • create a variable dictionary;
  • identify variables without labels;
  • add clear labels to pipeline-created variables;
  • preserve original NHANES variable names;
  • create readable categorical variables for analysis;
  • save variable metadata for reuse.

Why variable labels matter

NHANES variable names are designed to be compact and stable.

For example:

LBXHGB
RIAGENDR
RIDAGEYR
SDMVSTRA
SDMVPSU

These names are useful for programming, but they are not always immediately readable.

Variable labels provide descriptive meaning, such as:

Hemoglobin
Gender
Age in years
Masked variance pseudo-stratum
Masked variance pseudo-primary sampling unit

A reproducible pipeline should preserve both:

machine-readable variable names
+
human-readable variable labels

Do not replace original variable names unnecessarily

The original NHANES variable names should remain available because they:

  • correspond to official documentation;
  • make code easier to compare with NHANES examples;
  • reduce ambiguity;
  • support reproducibility;
  • help users locate variables in codebooks.

Readable labels and derived categorical variables should be added without destroying the original source names.

Create a label-extraction function

Add:

extract_variable_label <- function(
    variable) {

  variable_label <- attr(
    variable,
    "label"
  )

  if (
    is.null(
      variable_label
    ) ||
      length(
        variable_label
      ) == 0
  ) {
    NA_character_
  } else {
    as.character(
      variable_label[[1]]
    )
  }
}

Create a label-assignment helper

Add:

set_variable_label <- function(
    variable,
    label) {

  attr(
    variable,
    "label"
  ) <- label

  variable
}

This function returns the original variable with a label attached.

Preserve original coded variables

The variable:

RIAGENDR

should remain in the dataset.

Create an additional readable factor rather than replacing it.

cbc_demographics_labelled <-
  cbc_demographics_labelled |>
  dplyr::mutate(
    sex = factor(
      RIAGENDR,
      levels = c(
        1,
        2

      labels = c(
        "Male",
        "Female"

Assign a label:

cbc_demographics_labelled$sex <-
  set_variable_label(
    cbc_demographics_labelled$sex,
    "Participant sex"
  )

Why preserve RIAGENDR?

Keeping the original coded variable:

  • preserves the official NHANES source value;
  • allows verification against documentation;
  • avoids losing provenance;
  • supports reproducible recoding;
  • makes it possible to revise labels later.

The derived sex variable is intended for readable analysis and presentation.

Variable names, labels, and factor levels

These three concepts are different.

Variable name

Used directly in R code:

RIAGENDR

Variable label

Describes the meaning of the variable:

Gender

Factor labels

Describe individual coded values:

1 = Male
2 = Female

A well-documented analytical dataset can preserve all three.

Labels are metadata, not harmonization

Adding a readable label does not prove that a variable is comparable across cycles.

Before combining or interpreting a variable longitudinally, review:

  • wording;
  • units;
  • laboratory method;
  • specimen type;
  • eligibility;
  • lower detection limits;
  • coding;
  • documentation changes.

A label improves readability. It does not establish scientific equivalence.

Common mistakes

Renaming all NHANES variables immediately

This makes it harder to compare the data with official documentation and published code.

Replacing coded variables with factors

Keep the original source variable and create a derived readable version.

Writing labels from memory

Use the imported label or official documentation.

Assuming every unlabelled variable is wrong

Pipeline-created variables may simply require locally defined labels.

Treating labels as harmonization evidence

A common label does not prove that units, methods, or eligibility are consistent across cycles.

Losing labels during export

CSV files do not preserve R variable-label attributes.

Save an RDS dataset and a separate variable dictionary.

NoteWhy should original NHANES variable names be preserved?

They correspond to official documentation, support reproducibility, and make it easier to compare the pipeline with other NHANES code and publications.

NoteWhy create sex instead of replacing RIAGENDR?

RIAGENDR preserves the original coded source variable, while sex provides a readable factor for analysis and presentation.

NoteDoes assigning the same label across cycles prove that a variable is harmonized?

No. Harmonization also requires review of units, methods, eligibility, coding, specimen type, and documentation.
