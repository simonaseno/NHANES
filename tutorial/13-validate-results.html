Lesson 13: Validate the Merged Results

Run systematic post-merge checks before using the analytical dataset

Validate the structure, keys, coverage, provenance, variables, and merge outcomes of the NHANES CBC and Demographic analytical dataset.
NoteLearning objectives

By the end of this lesson, you should be able to:

  • validate the final analytical row count;
  • confirm the uniqueness of survey_cycle + SEQN;
  • verify survey-cycle coverage;
  • assess Demographic match completeness;
  • validate CBC and Demographic provenance;
  • confirm required analytical variables;
  • inspect missingness by cycle;
  • identify impossible or implausible values;
  • create a consolidated validation report;
  • stop the pipeline when critical checks fail.

Why post-merge validation is necessary

A successful join does not prove that the resulting dataset is analytically valid.

The merged dataset could still contain:

  • duplicated participant keys;
  • missing survey cycles;
  • unexpected row multiplication;
  • missing required variables;
  • incomplete Demographic matches;
  • lost provenance;
  • supplementary records;
  • implausible laboratory values;
  • structural missingness;
  • inconsistent coding across cycles.

Post-merge validation converts these expectations into explicit checks.

Where you are in the workflow

You currently have:

cbc_demographics_1999_2018

This dataset was created using a one-to-one left join between:

cbc_primary_1999_2018

and:

demographics_1999_2018

The explicit merge key is:

survey_cycle + SEQN

Flag clearly impossible hemoglobin values

For a basic data-integrity check, flag nonpositive values:

nonpositive_hemoglobin <-
  cbc_demographics_1999_2018 |>

    !is.na(
      LBXHGB

Count:

nrow(

Values outside an expected clinical range may require review, but thresholds should not be used casually to delete observations.

WarningPlausibility flags are not automatic exclusion rules

An unusual value can reflect:

  • a true extreme observation;
  • a measurement issue;
  • a coding issue;
  • a unit difference;
  • a changed method;
  • a data-entry or release problem.

Flag first. Investigate before excluding.

Validation does not replace scientific review

The checks in this lesson establish that the pipeline behaved as intended.

They do not prove that:

  • every variable is harmonized correctly;
  • laboratory methods are equivalent across cycles;
  • the correct survey weight has been selected;
  • all outliers are valid;
  • a planned statistical model is appropriate;
  • an unweighted summary is nationally representative.

Those questions require component documentation and analysis-specific review.

Common mistakes

Assuming a successful join is sufficient

A join can succeed while producing duplicate or incomplete records.

Treating all missing values as errors

Some missingness reflects eligibility, specimen collection, component availability, or cycle structure.

Deleting unusual laboratory values automatically

Unusual values should be flagged and investigated first.

Using one weight for every analysis

Weight selection depends on the component, subsample, cycles, and analytical population.

Validating only the final row count

Row counts are important, but keys, cycles, variables, provenance, match status, and value structure must also be checked.

Ignoring failed checks

A validation table is useful only when the pipeline stops or clearly warns when critical expectations are violated.

Knowledge check

NoteWhy should the final merged row count equal the primary CBC row count?

The merge uses the primary CBC dataset as the left analytical base. A one-to-one left join should add Demographic columns without adding or removing CBC rows.

NoteDoes an unusual hemoglobin value automatically mean the record should be deleted?

No. It should be flagged and investigated for measurement, coding, unit, method, or source issues before any exclusion decision is made.

NoteDoes passing pipeline validation make an unweighted analysis nationally representative?

No. National inference still requires the appropriate NHANES survey weights, strata, primary sampling units, and multi-cycle weighting procedures.
