Lesson 9: Import and Inspect the Downloaded NHANES Files

Read every XPT file, confirm its structure, and detect problems before combining datasets

Import downloaded NHANES XPT files, inspect variables and keys, validate record structure, and troubleshoot common import problems.
NoteLearning objectives

By the end of this lesson, you should be able to:

  • import an NHANES XPT file with haven::read_xpt();
  • confirm that a downloaded file contains readable data;
  • inspect dimensions, variable names, classes, and labels;
  • verify that SEQN exists;
  • inspect participant-key completeness and uniqueness;
  • compare imported structure across source files;
  • identify HTML error pages or incomplete downloads;
  • diagnose missing variables and unexpected classes;
  • create an inspection report for all downloaded files;
  • stop the pipeline when a critical source fails validation.

Why inspect files before combining them?

A downloaded file may exist and still be unsuitable for analysis.

For example, it may:

  • contain zero records;
  • be incomplete;
  • contain an HTML error page;
  • fail to import;
  • omit the expected participant identifier;
  • use an unexpected variable class;
  • represent a different examination or record level;
  • contain duplicate participant identifiers.

Inspection must occur before files are combined.

The workflow is:

Download
→ import
→ inspect
→ validate
→ classify
→ combine

Do not move directly from downloading to row-binding.

Where this lesson fits

You previously:

  • created the source catalog;
  • downloaded one test file;
  • downloaded all required source files;
  • created an acquisition manifest.

This lesson verifies that the downloaded files are structurally usable.

If the XPT file does not import

Use this section immediately when haven::read_xpt() fails.

WarningDo not continue to combining files

A file that cannot be imported must be investigated before row-binding or merging.

Confirm the project root

In the terminal, run:

pwd

The result should end with:

/NHANES

List the project files:

ls

Confirm that the exact file exists

In R, inspect:

test_import_record$local_path

Then run in the terminal:

ls -lh path/to/the/file.xpt

Replace the placeholder with the exact local path shown in R.

Check the file size

Run:

ls -lh data/raw

A file that is extremely small, zero bytes, or missing may indicate an incomplete download.

Inspect the file type

Run:

file path/to/the/file.xpt

A downloaded file may have an .xpt extension but actually contain:

  • HTML;
  • plain text;
  • an error response;
  • incomplete binary content.

If the result identifies HTML, the file is not a valid NHANES XPT dataset.

Inspect the beginning of a suspicious file

Use:

head -n 10 path/to/the/file.xpt

Only use this when the file command suggests text or HTML.

Do not use a text editor to modify a valid binary XPT file.

An HTML response may contain text such as:

Access denied
Page not found
Server error

Test the file directly from R

Run:

Rscript -e 'x <- haven::read_xpt("path/to/the/file.xpt"); print(dim(x)); print(head(names(x), 20))'

Replace the placeholder path.

If the direct test fails, the problem is with:

  • the file;
  • the path;
  • the R environment;
  • the haven installation.

Confirm that haven is installed

In the terminal, run:

Rscript -e 'cat(requireNamespace("haven", quietly = TRUE), "\n")'

Expected:

TRUE

If the result is FALSE, install haven from R before continuing.

Remove only the failed file

Do not delete the entire raw-data directory.

Remove only the affected file:

rm path/to/the/file.xpt

Then return to the download lesson and acquire it again.

Do not rename an invalid file merely to make it end in .xpt

The file extension does not change the file’s actual content.

  • the wrong source file was downloaded;

Do not generate row numbers or artificial IDs to replace a missing NHANES key.

Possible classes include:

  • numeric;
  • integer;
  • character;
  • haven_labelled;
  • date or time classes;
  • logical.

Do not convert a variable merely because its class differs from another cycle.

First determine whether:

  • the values have the same meaning;
  • the coding changed;
  • the label changed;
  • one source uses labelled numeric data;
  • one source stores text values.

Class harmonization should be scientifically justified.

Import every downloaded file

Create a safe import function:

import_nhanes_xpt <- function(
    local_path,
    dataset_id) {

  if (
    !file.exists(
      local_path
    )
  ) {
    stop(
      "Source file does not exist for ",
      dataset_id,
      ": ",
      local_path
    )
  }

  file_size <- file.info(
    local_path
  )$size

  if (
    is.na(
      file_size
    ) ||
      file_size <= 0
  ) {
    stop(
      "Source file is empty for ",
      dataset_id,
      ": ",
      local_path
    )
  }

  imported_data <- tryCatch(
    haven::read_xpt(
      local_path
    ),
    error = function(
        error) {

      stop(
        "Failed to import ",
        dataset_id,
        " from ",
        local_path,
        ": ",
        conditionMessage(
          error
        )
      )
    }
  )

  if (
    !is.data.frame(
      imported_data
    )
  ) {
    stop(
      "Imported source is not a data frame: ",
      dataset_id
    )
  }

  if (
    nrow(
      imported_data
    ) < 1
  ) {
    stop(
      "Imported source contains no records: ",
      dataset_id
    )
  }

  if (
    ncol(
      imported_data
    ) < 1
  ) {
    stop(
      "Imported source contains no variables: ",
      dataset_id
    )
  }

  if (
    !"SEQN" %in%
      names(
        imported_data
      )
  ) {
    stop(
      "Imported source does not contain SEQN: ",
      dataset_id
    )
  }

  imported_data
}

Why add provenance columns?

After files are combined, provenance columns allow each record to be traced back to:

  • the source dataset;
  • the survey cycle;
  • the NHANES component;
  • the file identifier;
  • the examination;
  • the analytical role.

This is especially important for the 2001–2002 second CBC examination.

Create a source inspection function

Add:

inspect_nhanes_source <- function(
    imported_data,
    dataset_id) {

  tibble::tibble(
    dataset_id =
      dataset_id,
    rows =
      nrow(
        imported_data
      ),
    columns =
      ncol(
        imported_data
      ),
    seqn_present =
      "SEQN" %in%
        names(
          imported_data
        ),
    missing_seqn =
      if (
        "SEQN" %in%
          names(
            imported_data
          )
      ) {
        sum(
          is.na(
            imported_data$SEQN
          )
        )
      } else {
        NA_integer_
      },
    distinct_seqn =
      if (
        "SEQN" %in%
          names(
            imported_data
          )
      ) {
        dplyr::n_distinct(
          imported_data$SEQN,
          na.rm = TRUE
        )
      } else {
        NA_integer_
      },
    duplicated_seqn_records =
      if (
        "SEQN" %in%
          names(
            imported_data
          )
      ) {
        sum(
          duplicated(
            imported_data$SEQN
          ) |
            duplicated(
              imported_data$SEQN,
              fromLast = TRUE
            )
        )
      } else {
        NA_integer_
      },
    first_variable =
      names(
        imported_data
      )[1],
    last_variable =
      names(
        imported_data
      )[
        ncol(
          imported_data
        )
      ]
  )
}

Common mistakes

Assuming that a downloaded file is valid

A file may exist but still contain an HTML error page or incomplete content.

Combining files before inspecting them

A malformed source can contaminate the combined dataset.

Creating an artificial SEQN

The participant identifier must come from the official source data.

Ignoring duplicate keys

Repeated identifiers must be investigated before combining files.

Converting every variable to character

This can destroy numeric meaning and create avoidable problems later.

Treating different components as though they should contain the same variables

CBC and Demographic files have different schemas and purposes.

Ignoring labels

Variable labels provide useful source documentation and should be preserved when possible.

Editing raw XPT files

Raw source files should remain unchanged.

Checkpoint

Confirm:

Knowledge check

NoteWhy inspect an XPT file after downloading it?

A file can exist and have a nonzero size while still containing invalid, incomplete, or unexpected content.

NoteWhy is SEQN essential?

SEQN is the NHANES participant identifier used to connect person-level component files.

NoteShould duplicated SEQN values be removed automatically?

No. They may reflect repeat examinations, supplementary records, or a structural issue that must be understood first.

NoteWhat should you check when haven::read_xpt() fails?

Confirm the path, file existence, file size, actual file type, haven installation, and whether an HTML error response was saved instead of an XPT file.

NoteWhy compare variable classes across source files?

Variables with the same name may be stored differently across cycles. These differences must be understood before row-binding.
