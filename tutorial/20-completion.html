The completed automated pipeline

Your primary script is:

nhanes_pipeline.R

The pipeline is designed to:

  • read and validate the NHANES source catalog;
  • download official source files;
  • record acquisition status and file hashes;
  • import and inspect the XPT files;
  • preserve the 2001–2002 second CBC examination separately;
  • combine ten primary CBC cycles;
  • combine ten Demographic cycles;
  • merge the components using survey_cycle + SEQN;
  • create and validate analytical variables;
  • save reusable RDS and CSV files;
  • analyze hemoglobin descriptively;
  • create four professional figures;
  • save final validation and run summaries.

The scientific decision about 2001–2002

The pipeline treats:

L25_B

as the primary 2001–2002 CBC source.

It preserves:

L25_2_B

as a separate supplementary second-examination dataset.

It does not blindly append the two files.

This protects the primary analytical structure from repeated or supplementary examination records.

Why both RDS and CSV?

RDS preserves R-specific information such as:

  • factor structure;
  • ordered factor levels;
  • variable attributes;
  • labels;
  • object classes.

CSV provides:

  • portability;
  • accessibility outside R;
  • compatibility with many analytical tools.

The formats serve different purposes.

Run the final analytical pipeline

Before rendering the website, run the analytical pipeline from the project root.

In the terminal:

Rscript nhanes_pipeline.R

To display the output and save a console log:

Rscript nhanes_pipeline.R 2>&1 | tee outputs/validation/complete_pipeline_console.log

After it finishes, check the exit status:

echo $?

Expected:

0

A zero exit status indicates that the R process completed without an unhandled error.

Confirm the four PNG files

In the terminal, run:

ls -lh outputs/figures/*.png

You should see four PNG files.

Important scientific limitation

The current hemoglobin analysis is:

unweighted and descriptive

It describes the analytical records included in the pipeline.

It is not automatically representative of the United States population.

WarningDo not call the current figures national estimates

The current analysis does not incorporate the complete NHANES complex survey design.

A professional figure theme does not replace:

  • survey weights;
  • strata;
  • primary sampling units;
  • multi-cycle weight construction;
  • design-based variance estimation.

What is required for population inference?

To extend the analysis to nationally representative estimates, determine:

  • the appropriate examination or component-specific weight;
  • the correct multi-cycle weight adjustment;
  • the relevant analytical eligibility criteria;
  • whether a subsample weight is required;
  • how to specify SDMVSTRA;
  • how to specify SDMVPSU;
  • how to estimate survey-adjusted means;
  • how to calculate design-based confidence intervals;
  • whether laboratory methods are comparable across cycles.

Example future survey-design structure

A future weighted analysis may use the survey package.

A general structure may resemble:

library(
  survey
)

nhanes_design <- survey::svydesign(
  ids =
    ~ SDMVPSU,
  strata =
    ~ SDMVSTRA,
  weights =
    ~ appropriate_multi_cycle_weight,
  nest =
    TRUE,
  data =
    weighted_analysis_data
)

This is a structural example only.

Do not use a weight until its appropriateness for the component, population, and combined cycles has been verified.

Extend the pipeline

The completed architecture can be adapted to additional CBC variables such as:

  • hematocrit;
  • red blood cell count;
  • mean corpuscular volume;
  • mean corpuscular hemoglobin;
  • mean corpuscular hemoglobin concentration;
  • white blood cell count;
  • platelet count.

For each analyte:

  1. confirm availability by cycle;
  2. verify labels and units;
  3. review laboratory documentation;
  4. inspect method changes;
  5. validate missingness;
  6. define the analytical population;
  7. identify the correct survey weight;
  8. create analyte-specific outputs.
